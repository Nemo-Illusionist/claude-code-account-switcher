# Личности: `doctor`, `lock`, `usage`

[← README](../../README.ru.md) · [English](../identity.md)

Под каким аккаунтом Anthropic реально находится каждая config-папка, как
закрепить его за ней и сколько лимита уже потрачено.

## Под каким аккаунтом config-папка (`doctor`)

`claude-acc add` и `claude-acc login` оба запускают `claude auth login` под персональным `CLAUDE_CONFIG_DIR`. С каким Anthropic-аккаунтом вы залогинились — тот и привязан к этой директории. Встроенного способа увидеть, *какой именно* аккаунт реально стоит за config dir, нет. Если случайно залогинились не той учёткой (browser auto-fill, забытая вкладка), переключение происходит молча: лимиты, история диалогов и биллинг перепутаются между «изолированными» аккаунтами без всяких признаков.

`claude-acc doctor` читает OAuth-токен каждого аккаунта из macOS Keychain (с fallback на `.credentials.json` для установок без Keychain), дёргает `https://api.anthropic.com/api/oauth/profile` и печатает реальные email, план и UUID:

```
$ claude-acc doctor
Проверка 2 аккаунт(ов):
  ✓ work      alice@anthropic.com  Max 20x  uuid=aa6c22d5-…
  ? personal  нет токена (запустите: claude-acc login personal)

1 из 2 аккаунтов в порядке.
```

Метка плана (`Max 20x` / `Max` / `Pro`) выводится из tier-флагов профиля и `rate_limit_tier`; для аккаунтов без распознаваемой подписки она опускается.

Это исключительно read-only аудит — ничего не перехватывается, запуск `claude` не блокируется. Запускайте когда хочется убедиться, что за config dir стоит ожидаемая личность. Требует `security`, `curl`, `jq`, `shasum` (всё предустановлено на macOS); Rust-бинарник использует нативные `serde_json` и `sha2`, шеллаутит только `security` и `curl`.

`doctor` ещё кэширует результат (email, план, UUID) в `~/.claude-switch/accounts/<name>/.account-info.json`, чтобы `list`, `usage`, `status` и `default` показывали личность рядом с каждым аккаунтом без повторных API-запросов:

```
$ claude-acc list
Аккаунты Claude Code:
  ★ work       (по умолчанию)  alice@anthropic.com   Max 20x  3д назад
    personal                   bob@anthropic.com     Pro      1ч назад *
    ~/.claude/                 charlie@personal.com  Max 5x   3д назад    (стандартный)

$ claude-acc status
Активный аккаунт: work <alice@anthropic.com> (привязан к my-project)

$ claude-acc default
По умолчанию: work <alice@anthropic.com>
```

`doctor` аудитит и стандартный `~/.claude/` (неуправляемая личность, к которой claude обращается когда нет ни link'а, ни настроенного default'а). Его кэш лежит в `~/.claude-switch/default.account-info.json`. Строка `~/.claude/` появляется в `list` только если вы реально залогинены в Claude Code со стандартным config-dir (или если `doctor` уже закэшировал identity для него).

Для скриптов `claude-acc doctor --json` отдаёт те же данные одним JSON-документом — а `claude-acc whoami` печатает email (или имя аккаунта как fallback) активного аккаунта, удобно для shell-prompt:

```bash
# В prompt:
PS1='[$(claude-acc whoami)] \$ '

# В скрипте:
case "$(claude-acc whoami)" in
    alice@anthropic.com) echo "work" ;;
    *)                   echo "other" ;;
esac
```

`*` после email означает что OAuth-токен изменился с момента записи кэша. Чаще всего это рутинный refresh токена (identity та же) — но если вы запускали `claude auth login` напрямую между запусками `doctor`, это напоминание что стоит перепроверить. Запустите `claude-acc doctor`, чтобы обновить кэш.

### Один логин, несколько настроек

Привязать две папки-аккаунта к **одному** логину Anthropic — вполне нормальный сценарий: так можно держать раздельные глобальные конфиги (разные `CLAUDE.md`, плагины, агенты, MCP-серверы, output styles) под одной подпиской и переключаться между ними по директориям. Когда `doctor` видит аккаунты с одной личностью, он помечает их `↔` — чтобы пересечение было осознанным и видимым, а не сюрпризом:

```
$ claude-acc doctor
Проверка 2 аккаунт(ов):
  ✓ minimal  alice@anthropic.com  Max 20x  uuid=aa6c22d5-…  ↔ та же личность, что и full
  ✓ full     alice@anthropic.com  Max 20x  uuid=aa6c22d5-…  ↔ та же личность, что и minimal

Все аккаунты в порядке.
```

Это просто пометка, а не ошибка — оба аккаунта делят логин (а значит и общие лимиты), различается только их локальный конфиг.

> **Пока только macOS.** Схема хеширования Keychain reverse-engineered из внутренностей Claude Code; на других платформах (где используется libsecret / Credential Manager) пока не работает.

## Закрепление аккаунта за личностью (`lock`)

`doctor` показывает, под каким аккаунтом залогинен каталог. Он не может
сказать, тот ли это аккаунт, который здесь **должен** быть, — это надо
помнить. Ломается это обычно на повторном входе: OAuth-флоу никогда не
спрашивает, какой аккаунт вы имели в виду, поэтому вход не из той сессии
браузера тихо перепривязывает конфиг-каталог, и все дальнейшие сессии уходят
не туда.

`lock` записывает ответ:

```bash
claude-acc lock work            # закрепить work за тем, под кем он сейчас
claude-acc lock work --force    # осознанно принять новую личность
claude-acc lock default         # стандартный ~/.claude тоже можно
```

`add` и `login` закрепляют автоматически при первом входе, так что команда
нужна для аккаунтов, созданных до появления закрепления, и для осознанного
перезакрепления. **Повторный вход существующее закрепление не двигает** —
именно этот подмен оно и должно показывать.

`doctor` сравнивает одно с другим и молчит, пока они сходятся:

```
$ claude-acc doctor
Проверка 2 аккаунт(ов):
  ✓ work        alice@corp.com  uuid=a72fe3df-3623-46b0-89ab-85770432d3fd  ⚠ РАСХОЖДЕНИЕ: закреплён за bob@personal.com (aa6c22d5-f7d1-4ac1-bb29-22abc90481c1), вход под alice@corp.com (a72fe3df-3623-46b0-89ab-85770432d3fd)
  ✓ ~/.claude/  bob@personal.com  Max 20x  uuid=aa6c22d5-f7d1-4ac1-bb29-22abc90481c1  (стандартный)

Расхождение значит, что каталог залогинен под аккаунтом, за которым он не закреплён, — работа отсюда уйдёт не туда. Вернуть: `claude-acc login <name>`. Принять новую личность: `claude-acc lock <name> --force`.
```

При расхождении `doctor` завершается ненулевым кодом — можно повесить
проверку на приглашение шелла или на шаг CI.

**Сравнение ничего не стоит.** Оно читает собственную запись Claude Code о
том, кто вошёл, — небольшой JSON рядом с каждым конфиг-каталогом, — поэтому
ни запроса к Keychain, ни обращения к сети, в отличие от остального `doctor`.
Ровно поэтому его не жалко звать часто.

**Решает только UUID.** Email у одного аккаунта может смениться, а
отображаемое имя у двух аккаунтов может совпасть; сравнение по чему-то более
мягкому давало бы и ложные расхождения, и пропущенные.

**Чего он не делает:** ничего не блокирует. `lock` и `doctor` сообщают, но
никогда не встают между вами и `claude`. Должен ли неверный аккаунт вообще
отказываться запускаться — это [#16](https://github.com/Nemo-Illusionist/claude-code-account-switcher/issues/16), пока открытый.

Закрепление лежит в `~/.claude-switch/accounts/<имя>/.identity-lock.json` —
кроме стандартного аккаунта, чьё уходит в
`~/.claude-switch/default.identity-lock.json`, а не внутрь `~/.claude/`,
который принадлежит Claude Code.

## Сколько лимита осталось (`usage`)

`claude-acc usage` показывает, сколько лимита уже израсходовано на каждом аккаунте, чтобы вы могли выбрать свежий аккаунт до того, как упрётесь в стену. Для каждого аккаунта (и стандартного `~/.claude/`, если в него выполнен вход) команда читает OAuth-токен, вызывает `https://api.anthropic.com/api/oauth/usage` и отображает окна **5 часов** и **7 дней** с баром, процентом и временем до сброса:

```
$ claude-acc usage
Использование Claude Code:
  ★ work  <alice@anthropic.com>  Max 20x
      5h  [████████░░░░░░░░░░░░]   42%  сброс через 2ч 14м
      7d  [██░░░░░░░░░░░░░░░░░░]   11%  сброс через 5д 17ч
    personal  <bob@anthropic.com>  Pro
      5h  [░░░░░░░░░░░░░░░░░░░░]    0%  доступно сейчас
      7d  [░░░░░░░░░░░░░░░░░░░░]    0%  сброс через 6д 3ч
```

В отличие от `doctor`, сами цифры использования всегда тянутся вживую — данные изменчивы, поэтому не кэшируются. Email/план рядом с аккаунтом берутся из кэша `doctor`, так что один раз запустите `claude-acc doctor`, чтобы их заполнить. Аккаунты без токена показывают `нет токена (запустите: claude-acc login <имя>)`; недоступный API — `токен есть, API недоступен`. Зависимости и ограничение платформы те же, что у `doctor` (`security`, `curl`, `jq`, `shasum`; пока только macOS).
