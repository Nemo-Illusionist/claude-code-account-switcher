# Статус-панель

[← README](../../README.ru.md) · [English](../statusline.md)

Claude Code умеет показывать настраиваемую панель внизу экрана. `claude-acc statusline` рисует её так, что **первым идёт аккаунт, под которым запущена сессия** — то, чего сам Claude Code показать не может — затем git-ветка, модель, проект и индикатор контекстного окна:

```
work │ ⎇ main │ Opus 4.8 (1M context) │ my-repo │ ▓▓▓░░░░░░░  39%
```

Установить в `settings.json` активного аккаунта одной командой:

```bash
claude-acc statusline --install
```

Потом перезапустите Claude Code. Команда читает session-JSON Claude Code со stdin — данные бесплатные, без запросов к API. Имя аккаунта берётся из `CLAUDE_CONFIG_DIR`. Цвета уважают `NO_COLOR`.

### Что показывает индикатор и чем он не является

Это **контекстное окно текущей сессии**, из `context_window.remaining_percentage`, посчитанное от того окна, в которое сессия реально зажата, с цветом зелёный → жёлтый → оранжевый → жирный красный по мере приближения автокомпакта. В начале сессии, пока Claude Code не заполнил этот блок, индикатор не показывается.

Это **не** лимит вашей подписки. Он — отдельное число, и показывает его [`claude-acc usage`](identity.md#сколько-лимита-осталось-usage): окна 5 часов и 7 дней. Совпадать эти две цифры не будут никогда, потому что меряют разное: одна — насколько заполнен текущий разговор, другая — сколько израсходовано от плана. Именно о такой путанице была [#140](https://github.com/Nemo-Illusionist/claude-code-account-switcher/issues/140), и причиной были эти же страницы — они ещё долго описывали 5-часовое чтение после того, как индикатор перестал его показывать.

Число — это израсходованная доля того окна, **в которое зажата эта сессия**, посчитанная от той же суммы токенов, от которой считает Claude Code, поэтому читается так же: 393.5k из 1M — это 39% и там, и здесь. (Собственная строка Claude Code дополнительно вычитает из окна резерв под вывод, до 20k токенов, так что на маленьком окне её цифра идёт на несколько пунктов впереди этой.)

Зажмите сессию в меньшее окно — и индикатор будет считать от него. Те же 393.5k при окне 400k читаются как 98%, а не 39%, — и отсчёт Claude Code ведёт именно к 400k. В session-JSON приходит только окно *модели*, поэтому меньшее разрешается здесь, в том же порядке, в каком это делает Claude Code: сначала `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, затем первый по приоритету файл настроек, где окно задано, и никогда больше окна самой модели.

| Где | Ключ |
|---|---|
| переменная окружения | `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, окно в токенах — понимаются `400k` и `0.5m`, значение вне границ зажимается в них, и она приоритетнее любых настроек |
| `<проект>/.claude/settings.local.json`, затем `.claude/settings.json`, затем `settings.json` аккаунта | `modelSettings.<модель>.autoCompactWindow` для одной модели, иначе `autoCompactWindow` верхнего уровня |

*Настройка* вне диапазона 100000–1000000, который принимает Claude Code, игнорируется здесь так же, как и там, вместе с нецелой — зажимается только переменная окружения, и эта асимметрия тоже его собственная, — а `"auto"` означает, что модель остаётся при своём окне.

Блок модели называйте каноническим именем. `claude-opus-5` совпадает и с датированным, `[1m]`, Bedrock- и Vertex-написаниями той же модели, но **алиас** — `opus`, `sonnet`, `opusplan` — Claude Code разрешает через свой реестр моделей, до которого статус-панель не достаёт, так что заданное так окно здесь не увидят.

Три источника **не** читаются: управляемые настройки организации, flag-настройки, которые передаёт хост, и серверные и экспериментальные значения по умолчанию, к которым Claude Code обращается ниже файлов настроек. Если окно урезано одним из них, индикатор будет показывать меньше, чем есть.

Про автокомпакт знает цвет: часть этого окна остаётся в запасе под сводку компакта, то есть стена наступает раньше, чем индикатор заполнится. Серьёзность считается от окна, уменьшенного на 16.5%, а не от всего окна, и красный благодаря этому продолжает означать «компакт вот-вот сработает», а не произвольную долю:

| | |
|---|---|
| зелёный | меньше половины полезного окна |
| жёлтый → оранжевый | за половиной, затем за двумя третями |
| жирный красный | компакт уже близко |

То есть цифры отвечают на вопрос *насколько полон этот разговор*, а цвет — *насколько близка стена*. В прежних версиях цифры тоже нормировались, из-за чего одна и та же сессия читалась как 47% здесь и 39% в приложении — два числа для одной величины, и на экране ничто не подсказывало, какое из них какое.

Хотите прописать вручную? Укажите в `statusLine` установленный бинарник:

```json
{
  "statusLine": { "type": "command", "command": "~/.claude-switch/bin/claude-acc statusline" }
}
```

> Статус-панель — фича Rust CLI: `statusLine` в Claude Code запускает путь к бинарнику/скрипту, а shell-дистрибуция не может дать его как sourced-функцию.
