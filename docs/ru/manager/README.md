# Claude Accounts: менеджер

[English](../../manager/README.md)

Необязательное приложение для macOS и значок в строке меню для этого инструмента: аккаунты, их личность и использование, привязки к директориям — в одном окне. Оно построено на том же коде Rust, что и CLI, и лежит в `apps/manager`, вне корневой сборки `cargo`, так что пользователи только CLI ничего лишнего не собирают и не устанавливают.

Не путать с `claude-acc desktop` — это профили Claude Desktop ([руководство](../desktop.md)).

Готовой сборки нет: менеджер собирается из исходников и не подписан ([#165](https://github.com/Nemo-Illusionist/claude-code-account-switcher/issues/165)).

## Использование

Claude Code должен быть уже установлен и доступен в `PATH` окружения входа Terminal. Приложение содержит свой `claude-acc` той же версии и запускает в Terminal именно его, поэтому для запуска, входа и остального в окне отдельная установка не нужна. Исключения — строка состояния и проверка `--resume` во враппере `claude`: обе запускают CLI, установленный в `~/.claude-switch/bin` командой `claude-acc install`.

1. **Аккаунты:** все настроенные аккаунты и стандартный `~/.claude` — личность, тариф, состояние pin и окна 5 часов и 7 дней. Details показывает, откуда взят каждый факт и какие версии CLI есть.
2. **Использование:** окно открывается на локальных записях. Refresh status запрашивает API профиля и использования. У каждого показания указан его возраст, который растёт, пока окно открыто; через десять минут показание помечается устаревшим. Для окна, чьё время сброса прошло, вместо числа показано «Reset passed». Автообновление включается отдельно: каждые 5, 15 или 30 минут.
3. **Open Claude:** новое окно Terminal со встроенным `claude-acc run <account>`. Работающие сессии не затрагиваются. Pin, расходящийся с вошедшей личностью или нечитаемый, блокирует запуск, пока аккаунт не перезакреплён (ниже) или снова не вошёл под закреплённой личностью. Подтверждение сообщает, что запуск *начался*, когда Terminal его выполнил, — это не то же самое, что вход Claude.
4. **Добавить аккаунт / войти заново:** открывает существующий вход CLI в Terminal. Вход происходит в Terminal; приложение не видит паролей и не хранит собственных учётных данных. Затем обновите данные. Новый аккаунт может начать с настроек стандартного, как `claude-acc add --seed`: для этого отметьте флажок в подтверждении. **Import an existing folder instead** принимает существующую config-папку вроде `~/.claude-work` без повторного входа, как [`claude-acc import`](../accounts.md#импорт-существующей-config-папки): по умолчанию копией, с флажком — перемещением. На macOS приложение затем, как и CLI, копирует вход папки из Keychain в новый аккаунт: читает эту запись и записывает её под новым именем. Уже управляемый аккаунт, ссылка или папка, содержащая собственное хранилище инструмента, отклоняются, как и перемещение стандартного `~/.claude`.
5. **Сделать по умолчанию:** действует только на новые контексты без привязки и требует подтверждения.
6. **Закрепить личность:** незакреплённый аккаунт можно закрепить за личностью, под которой он вошёл, как это делает `claude-acc lock`. Если pin и вошедшая личность расходятся или pin нечитаем, запуск блокируется, а меню предлагает перезакрепить аккаунт за текущей личностью; только так приложение заменяет pin.
7. **Скопировать настройки из стандартного аккаунта:** управляемый аккаунт получает `settings.json`, `CLAUDE.md`, агентов, команды, стили вывода, skills и плагины из `~/.claude`, как [`claude-acc clone-settings`](../accounts.md#наследование-конфига-из-claude). Файл или папка, которые у аккаунта уже есть, сохраняются, плагины копируются только в аккаунт без установленных плагинов, а подтверждение перечисляет скопированное.
8. **Установить строку состояния:** добавляет в `settings.json` выбранного аккаунта `statusLine`, запускающий `claude-acc statusline`, как [`claude-acc statusline --install`](../statusline.md). Остальное содержимое файла сохраняется. Собственная строка состояния заменяется только после повторного подтверждения; `settings.json`, который не является корректным JSON или является ссылкой, не трогается; нужен CLI, установленный в `~/.claude-switch/bin`, — его и запускает команда.
9. **В корзину:** директория управляемого аккаунта перемещается в корзину вместе с его привязками; если он был по умолчанию, по умолчанию становится стандартный аккаунт. Стандартный аккаунт удалить нельзя. Если корзина не принимает перемещение, ничего не меняется; удаление напрямую остаётся за `claude-acc remove --purge`.
10. **Проекты:** выберите или введите папку, чтобы увидеть действующий аккаунт и привязку, от которой он унаследован, затем сохраните или удалите привязку. Побеждает ближайшая привязка. Привязку уже отсутствующей папки всё равно можно удалить.
11. **Сессии:** метаданные сессий всех аккаунтов, новые первыми. **Copy to…** копирует одну сессию вместе с transcript субагентов в другой аккаунт, как `claude-acc session copy`; оригинал остаётся на месте. Если в аккаунте назначения эта сессия уже есть, диалог об этом говорит, а кнопка её заменяет. Продолжение остаётся в Terminal ([руководство по сессиям](../sessions.md)). Над списком можно включить или выключить проверку `--resume` во враппере `claude`, который кладёт в `PATH` отдельно установленный CLI (`claude-acc install`), как [`claude-acc resume-hook on|off`](../sessions.md#та-же-проверка-для-голого-claude---resume-resume-hook); показывается сохранённое значение, которое терминал с заданной `CLAUDE_ACC_NO_RESUME_HOOK` всё равно может переопределить.

Закрытие окна оставляет значок в строке меню. Из него можно запустить аккаунт в домашней директории, открыть Проекты, обновить данные или выйти — всё это работает и с закрытым окном. Клавиши: ⌘1/2/3 — страницы, ⌘N — добавить аккаунт, ⌘R — обновить.

## Сборка и проверки

Нужны macOS, Xcode Command Line Tools, Rust 1.90 или новее с clippy и rustfmt (закреплённые крейты Tauri требуют 1.90), Node 22.19 или новее и npm.

```sh
cd apps/manager
npm ci --ignore-scripts
npm run check
npm test
npm run manager:build
```

`--ignore-scripts` выбран намеренно: ни одному пакету в дереве не нужен install-скрипт (esbuild и fsevents поставляют готовые бинарники), а без них install-хук зависимости не выполняется с правами вашей учётной записи.

`manager:build` запускает `prepare:cli`, который собирает CLI и копирует его с суффиксом целевой платформы, нужным Tauri, а затем собирает бандл. Приложение появляется в `apps/manager/src-tauri/target/release/bundle/macos/`. Для разработки — `npm run manager:dev`.

Собственные проверки крейта, после `npm run build` и `npm run prepare:cli`:

```sh
cargo fmt --manifest-path apps/manager/src-tauri/Cargo.toml --all --check
cargo clippy --manifest-path apps/manager/src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path apps/manager/src-tauri/Cargo.toml --release
```

Чтобы попробовать приложение, не трогая настоящие аккаунты, `node apps/manager/scripts/create-review-fixture.mjs` создаёт два тестовых аккаунта, две привязки и сессию в игнорируемой git папке `artifacts/review-home`. Запустите собранное приложение с этой папкой в качестве домашней:

```sh
HOME="$PWD/artifacts/review-home" \
  "apps/manager/src-tauri/target/release/bundle/macos/Claude Accounts.app/Contents/MacOS/claude-acc-manager"
```

У workflow Manager два job. `checks` запускается на каждый pull request, включая изменения только в документации, поэтому может быть обязательной проверкой: проверка типов и тесты фронтенда, затем fmt, clippy и тесты крейта. `bundle` собирает неподписанный `.app` после успешного `checks`: на pull request — только если изменились `apps/manager/`, `src/` или корневые манифесты, а после merge в `master` и при ручном запуске — всегда. Ничего не публикуется.

## Как это устроено

- **`claude_acc::gui`** (`src/gui.rs`) — единственная часть библиотеки, которую использует менеджер: типизированные результаты без секретов и машинные коды ошибок; разрешение привязок, запись и правило запуска идут через собственный код CLI. Форма данных закреплена файлом `src/gui.contract.json`. См. [контракт](contract.md).
- **Оболочка** (`apps/manager/src-tauri`) владеет snapshot аккаунтов: строит их по одному, нумерует и отправляет и в строку меню, и в окно, так что ни одно не зависит от того, открыто ли другое. Обновление, ожидавшее в очереди за другим, использует его результат, а не повторяет сетевые запросы. Чтения, записи и запуски не ждут обновления.
- **Фронтенд** (`apps/manager/src`) обращается к оболочке только через `api.ts` — единственный модуль, импортирующий `@tauri-apps/*`; это проверяется тестом. У JavaScript нет доступа к файловой системе, shell или HTTP, а политика безопасности содержимого ограничивает его ресурсами сборки и IPC.
- **Запуск:** Terminal выполняет файл `.command` в новой login-оболочке, которая ничего не наследует от приложения. Скрипт запуска — неизменяемый код, читающий один приватный файл запроса (0600, в каталоге 0700) как данные. Он экспортирует `HOME` приложения, чтобы CLI разрешал те же аккаунты, что показало окно, сбрасывает `CLAUDE_SECURESTORAGE_CONFIG_DIR` и удаляет запрос при старте — так приложение узнаёт, что он выполнился. Пути, имена аккаунтов и переведённый текст никогда не становятся исходным кодом shell или AppleScript.

## Язык

Тексты менеджера собраны в одном месте на каждой стороне: `apps/manager/src/i18n.tsx` для окна и `apps/manager/src-tauri/src/copy.rs` для строки меню, диалогов и подсказки в Terminal. На обеих сторонах язык без какой-либо записи не собирается: таблицу окна проверяет `tsc`, а `copy.rs` перебирает варианты исчерпывающе, как и `i18n.rs` в CLI. Ни то, ни другое не проверяет, что значение переведено, и ничто не подставляется из одного языка в другой ([#166](https://github.com/Nemo-Illusionist/claude-code-account-switcher/issues/166)). Пока заполнен только английский. Русскую таблицу пишет сопровождающий, а то, как менеджер выбирает язык, ещё обсуждается.

## Ограничения

- Пока только macOS. Скрипт запуска — единственный платформенно-зависимый код, а на других платформах он возвращает явную ошибку «только macOS».
- Без подписи. macOS один раз попросит разрешить первый запуск; см. [#165](https://github.com/Nemo-Illusionist/claude-code-account-switcher/issues/165).
- Использование и личность берутся из тех же недокументированных API и записей Keychain, что и в CLI, с теми же оговорками. Локальная запись о личности не доказывает действующий вход.
- Symlink внутри хранилища аккаунтов (каталог аккаунта, файл учётных данных или личности, `config` или `links`) отклоняется. Само хранилище может находиться за symlink, например домашняя папка на другом томе. Папка проекта, доступная через symlink, разрешается в физический путь, как рабочая директория CLI. Пути с `=` нельзя привязать: формат `links` их не представляет.
- Запись в `config` и `links` берёт ту же блокировку, что CLI и `claude-switch.sh` (скрипт выполняет запись без блокировки, если не получает её за пять секунд).
- Нет удаления аккаунтов и сессий, ротации, телеметрии, автообновления и запуска при входе в систему.
