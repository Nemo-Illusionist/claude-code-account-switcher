# Необязательный менеджер Claude Accounts

[English](../../gui/README.md)

Необязательный интерфейс Tauri 2 + React для существующего CLI, только для macOS. CLI собирается отдельно без зависимостей GUI. Готовой сборки нет: соберите приложение из исходников, как описано ниже. Предложено в [#158](https://github.com/Nemo-Illusionist/claude-code-account-switcher/issues/158).

## Работа с приложением

Откройте `Claude Accounts.app` из локальной сборки или перетащите его из DMG в Applications. Локальная сборка имеет ad-hoc подпись; **подписи Developer ID и notarization нет**. Claude Code должен быть установлен и доступен в окружении входа Terminal. Для запуска не нужны Rust, Node, репозиторий или отдельная установка `claude-acc`.

1. **Accounts:** показывает настроенные каталоги и стандартный аккаунт `~/.claude`. Details & diagnostics показывает источник личности, привязку identity pin, известную подписку и версии CLI.
2. **Add account:** введите имя и подтвердите создание. Встроенный CLI откроет существующий вход Claude в Terminal. После входа вернитесь и обновите данные. Повторный вход доступен в меню аккаунта. Приложение не собирает учётные данные.
3. **Open Claude:** открывает новую сессию Terminal с явно выбранным аккаунтом. Работающие процессы не переключаются. Обнаруженное несовпадение identity pin или повреждение pin блокирует запуск до исправления через CLI. Подтверждение говорит «запущено», когда Terminal действительно выполнил запуск и передал управление CLI. Если macOS ещё спрашивает разрешение — что запрос ожидает.
4. **Make default:** требует подтверждения и влияет на новые контексты без привязки. Работающие сессии не переключаются.
5. **Projects:** выберите каталог, проверьте действующий аккаунт и ближайшую родительскую привязку, выберите аккаунт и подтвердите Save binding. Более близкая дочерняя привязка имеет приоритет. Remove возвращает наследование. Можно удалить привязку уже отсутствующего каталога.
6. **Usage:** Refresh status запрашивает личность и использование окон 5 часов / 7 дней. При запуске читаются только локальные записи. У каждого показания указано, сколько времени назад оно снято. Возраст продолжает расти, пока окно открыто, а через десять минут показание помечается устаревшим. Для окна, чьё время сброса прошло, показано “Reset passed” без процента — и для live, и для кэшированных показаний. Ошибки API и отсутствие учётных данных не маскируются. Автообновление включается отдельно: 5, 15 или 30 минут.
7. **Sessions:** аккаунт, сохранённый slug проекта, ID, размер, время изменения и наличие копий. Новые записи идут первыми. Копирование и продолжение через GUI отложены; используйте CLI и его предупреждения о конфликтах, сохраняя источник:

   ```sh
   claude-acc session copy <session-id> --to <destination-account>
   cd /original/project
   claude-acc run <destination-account> --resume <session-id>
   ```

   Используйте установленный совместимый CLI или `claude-acc` внутри `Contents/MacOS` приложения. Первый запрос в другом аккаунте может потребовать перестроения кэша промпта. Автоматической ротации аккаунтов и фоновой синхронизации нет.

Закрытие окна оставляет приложение в строке меню. Меню позволяет запустить аккаунт из домашнего каталога, открыть привязки проектов, обновить статус, вернуть окно или выйти. В меню указан источник usage, а не глобальный активный аккаунт. Клавиши: ⌘1/2/3 — разделы, ⌘N — добавление, ⌘R — обновление.

## Сборка и проверки

Нужны macOS, Xcode Command Line Tools, stable Rust с clippy/rustfmt, Node **22.19+**, npm. Desktop crate отделён от корневого пакета; корневые Cargo-команды не собирают Tauri.

```sh
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
cargo build --release
cargo test --release
cd apps/desktop
npm ci
npm run check
npm test
npm run desktop:build
```

Чтобы попробовать приложение, не трогая настоящие аккаунты, `node apps/desktop/scripts/create-review-fixture.mjs` создаёт два тестовых аккаунта, привязки и сессию в `artifacts/review-home`. Запустите собранное приложение с этой папкой в качестве домашней: `HOME="$PWD/artifacts/review-home" "apps/desktop/src-tauri/target/release/bundle/macos/Claude Accounts.app/Contents/MacOS/claude-acc-desktop"`.

`prepare:cli` собирает CLI с суффиксом целевой платформы для Tauri. `desktop:build` вызывает его автоматически. Для разработки — `npm run desktop:dev`. Добавьте `~/.cargo/bin` в PATH. Артефакты: `apps/desktop/src-tauri/target/release/bundle/{macos,dmg}`.

Нативные проверки после `npm run prepare:cli` и `npm run build`:

```sh
cargo fmt --manifest-path apps/desktop/src-tauri/Cargo.toml --all --check
cargo clippy --manifest-path apps/desktop/src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml --release
```

Desktop CI проверяет macOS без публикации. Корневой CI сохраняет проверки CLI на macOS/Linux/Windows. Desktop-пакеты и запуск Terminal на Windows/Linux отложены; переносимый код UI не означает проверенную сборку.

## Архитектура и контракт

Корневая библиотека `claude_acc` содержит модули конфигурации, личности, usage, разрешения каталогов, сессий, окружения и quoting, так что бинарник CLI и desktop-крейт используют одну реализацию. Команды CLI не меняются. Для desktop-приложения предназначен только `gui`; остальные модули помечены `#[doc(hidden)]` и стабильность не обещают. `gui` задаёт типизированные результаты с serde-сериализацией и машинные коды ошибок. Там же живёт политика аккаунтов: проверки имён и хранилища, разрешение привязок и то, можно ли выполнить запуск. Учётные данные, хэши токенов, сырые конфигурации и переписки не сериализуются. См. [контракт](contract.md).

Нативный backend владеет snapshot аккаунтов. Он строит их по одному (при live-обновлении — по потоку на аккаунт), нумерует каждый и отправляет и в строку меню, и в окно, так что каждое работает без другого. Обновление, ожидавшее в очереди за другим, использует его результат, а не повторяет сетевые запросы. Чтения, записи и запуски не ждут обновления, и каждая команда выполняется вне главного потока. Доступны только именованные Tauri-команды. У JavaScript нет доступа к файловой системе, HTTP, shell или удалённым origins. CSP разрешает ресурсы сборки и локальный IPC. В localStorage хранятся только тема и интервал; данные аккаунтов остаются в памяти.

Запуск использует `open -a Terminal` с типизированным аргументом файла. Terminal выполняет его в новой login-оболочке, которая ничего не наследует от приложения. Постоянный POSIX-скрипт читает один приватный файл запроса (0600, в каталоге 0700) как данные и передаёт аргументы встроенному CLI в кавычках. Пути и имена не подставляются в исходный shell/AppleScript. Скрипт экспортирует `HOME` приложения, чтобы CLI разрешал те же аккаунты, что показало приложение, и удаляет запрос сразу после чтения — по этому удалению приложение и считает запуск выполненным. CLI сохраняет очистку auth-переменных, Keychain snapshot/restore при входе, identity pins и изоляцию. Launcher удаляет shared credential-store override; live-обновление GUI отказывает при таком override, чтобы не спутать личности.

## Границы и ограничения

- GUI MVP на английском; интерфейс CLI на английском/русском сохранён.
- API/Keychain используются из CLI с его ограничениями недокументированных механизмов. Нового OAuth нет. Локальная запись личности не подтверждает успешный сетевой вход.
- Symlink-каталоги аккаунтов и файлы личности/учётных данных отклоняются. Symlink проекта разрешается в физический путь как cwd CLI. Формат CLI не позволяет сохранить привязку пути с `=`. Управляющие символы и переносы запрещены; Unicode, пробелы и апострофы поддерживаются.
- Записи используют формат и setters CLI. Каждое чтение-изменение-запись держит эксклюзивную блокировку `~/.claude-switch/.config.lock` и заменяет файл через rename, поэтому приложение и одновременно работающий `claude-acc` не теряют изменения друг друга и не оставляют обрезанный файл. `claude-switch.sh` берёт ту же блокировку, а если не получает её за пять секунд, выполняет прежнюю запись без блокировки.
- Диагностика показывает внешний CLI в стандартном месте установки. Приложение запускает собственный CLI нужной версии; внешний CLI не обновляется автоматически.
- Запуск со статусом «запущено» означает, что скрипт выполнился и передал управление встроенному CLI, а не что Claude вошёл в аккаунт. Ошибки видны в Terminal. Завершение входа/создания видно после обновления.
- Для сессий показываются сохранённые slugs; исходные пути не угадываются и содержимое не читается. Копирование/продолжение через GUI отложены.
- Нет удаления аккаунтов/сессий, телеметрии, облачного хранилища, автозапуска, автообновления, публичной публикации и notarization.
